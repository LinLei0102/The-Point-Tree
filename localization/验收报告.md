## 四、已知取舍

1. **`PP` / `PF` / `MP` 等缩写不译**。它们出现在按钮与价格里（`2 PP`、`x20 PF`），
   译成「2 威望点数」会把本来就窄的按钮撑开。术语表已统一此口径。
2. **成就格子里的小字会略微溢出格子边界**。这是原版模板 `<span><br><h3>名字</h3><br></span>`
   的问题（`h3` 处于 inline 上下文，计算宽度为 0），英文原版同样如此，与汉化无关，未做修改。
3. **更新日志里的版本号与内部代号**（`v3.5.7.1`、`MM10-15`、`ErUp 35`）保留原样，
   只有自然语言部分译为中文。
4. **主题名 `Void` / `Verdant` / `Lava` / `Sky` 保留英文**：它们同时是主题 id，
   译名会与设置页存储值不一致。
5. **浏览器自带 UI 无法汉化**：对话框的「确定 / 取消」按钮、地址栏、右键菜单、
   「离开此网站？」提示都由浏览器绘制，跟随浏览器界面语言；页面能控制的只有
   `alert`/`confirm`/`prompt` 的**正文**和标签页标题，这两处已处理。

## 五、维护方式

```bash
cd "D:/自制产物/点数树 汉化/tools"
node extract.js      # 源码 → strings.json / strings.tsv（运行态字符串清单）
node worklist.js     # 过滤模板/base64/CSS/代码 → work/*.json（按文件分组的待译清单）
# 翻译：work/<file>.json 的每一条，对应 zh/<file>.zh.json 同下标的译文（数组）
node zip.js          # 对拍 → parts/<file>.json（exact / fragment 两桶）
node build_dict.js   # 合并 → repo/localization/zh_CN.js（自动去重 + 生成术语表数据）
node coverage.js     # 无头浏览器全层遍历，输出 coverage.json（英文残留审计）
node probe.js        # 单页截图 / 单点探测（--tab= --shot= --eval= --url=）
```

上游更新后：重跑 `extract.js` → `worklist.js`，`work/` 里新增的条目即是新文案，
翻译后重跑 `zip.js` + `build_dict.js` 即可；`zh_CN.js` 永远由脚本生成，不手改。
